## 📖 معرفی (Overview)

این راهنما نحوه دریافت و تمدید خودکار گواهی SSL از **Let's Encrypt** برای آدرس‌های IP عمومی (Public IP) را با استفاده از بخش داخلی مدیریت SSL در پنل **3X-UI** توضیح می‌دهد؛ بدون اینکه نیازی به متوقف کردن **Nginx** یا ایجاد اختلال در سایر سرویس‌های در حال اجرا روی پورت‌های `80` و `443` باشد.

---

## ⚠️ مشکل چیست؟

پنل 3X-UI برای دریافت گواهی SSL روی IP، از ابزار `acme.sh` در حالت **Standalone** استفاده می‌کند. حالت Standalone به یک پورت HTTP آزاد نیاز دارد. با این حال، اگر Nginx از قبل روی پورت `80` در حال گوش دادن (Listen) باشد، فرآیند صدور گواهی با خطای زیر شکست می‌خورد:

<div dir="ltr">

```text
tcp port 80 is already used by nginx
Please stop it first

```

زمانی که چندین اپلیکیشن یا وب‌سایت به Nginx وابسته هستند، متوقف کردن آن راه‌حل عملی و مناسبی نیست.

---

## 💡 راه‌حل

به‌جای متوقف کردن Nginx، آن را طوری پیکربندی می‌کنیم که درخواست‌های اعتبارسنجی `ACME HTTP-01` را به یک پورت محلی جداگانه که `acme.sh` روی آن اجرا می‌شود، فوروارد (Forward) کند. به این ترتیب هر دو سرویس به‌طور هم‌زمان و بدون قطعی کار خواهند کرد.

---

## 🏗️ معماری سیستم (Architecture)

```text
                       Internet
                          |
                          |
                    Public Port 80
                          |
                          v
                   +-------------+
                   |    Nginx    |
                   |   Port 80   |
                   +-------------+
                          |
                          |
              /.well-known/acme-challenge/
                          |
                          v
                   +-------------+
                   | 127.0.0.1   |
                   |   :18080    |
                   |             |
                   |   acme.sh   |
                   | Standalone  |
                   +-------------+
                          |
                          v
                    Let's Encrypt

```

| بخش (Component) | وظیفه (Responsibility) |
| --- | --- |
| **Nginx** | مدیریت ترافیک عمومی HTTP روی پورت `80` |
| **acme.sh** | انجام اعتبارسنجی ACME HTTP-01 روی پورت `18080` |
| **3X-UI** | مدیریت فرآیند صدور و تمدید گواهی SSL |
| **Let's Encrypt** | اعتبارسنجی مالکیت IP و صدور گواهی SSL |

### نحوه عملکرد

۱. سرویس Let's Encrypt یک درخواست اعتبارسنجی HTTP-01 به پورت `80` ارسال می‌کند.
۲. وب‌سرور Nginx این درخواست را دریافت می‌کند.
۳. وب‌سرور Nginx مسیر چالش ACME را به آدرس `127.0.0.1:18080` هدایت می‌کند.
۴. ابزار `acme.sh` به درخواست اعتبارسنجی پاسخ می‌دهد.
۵. سرویس Let's Encrypt مالکیت IP سرور را تایید کرده و گواهی را صادر می‌کند.

> ترافیک عادی HTTP همچنان طبق پیکربندی فعلی Nginx شما پردازش می‌شود.

## 📋 پیش‌نیازها (Requirements)

پیش از شروع، از داشتن موارد زیر اطمینان حاصل کنید:

* یک سرور لینوکس دارای آدرس IPv4 عمومی.
* پنل 3X-UI نصب و در حال اجرا باشد.
* وب‌سرور Nginx نصب و روی پورت `80` در حال اجرا باشد.
* دسترسی Root یا `sudo`.
* باز بودن پورت عمومی TCP `80` از سمت اینترنت.
* یک پورت محلی (Local TCP) آزاد برای شنودگر ACME.

> در این راهنما از پورت **`18080`** به‌عنوان پورت اختصاصی ACME استفاده شده است. در صورت نیاز می‌توانید پورت آزاد دیگری انتخاب کنید.

### 📌 درباره گواهی‌های IP در Let's Encrypt

سرویس Let's Encrypt از صدور گواهی برای آدرس‌های IP عمومی با استفاده از پروفایل **کوتاه‌مدت (Short-Lived)** پشتیبانی می‌کند. مدت اعتبار این گواهی‌ها حدود **۱۶۰ ساعت (۶ روز و ۱۶ ساعت)** است؛ بنابراین تنظیم تمدید خودکار برای جلوگیری از منقضی شدن گواهی ضروری است.

---

## 🔍 مرحله ۱: بررسی وضعیت پورت‌های در حال استفاده

پورت‌هایی که در حال حاضر استفاده می‌شوند را بررسی کنید:

```bash
sudo ss -lntp | grep -E ':(80|443|8080|18080)\b'

```

**نمونه خروجی:**

```text
LISTEN 0 511 0.0.0.0:80   0.0.0.0:* users:(("nginx",pid=29744,fd=7))
LISTEN 0 511 0.0.0.0:443  0.0.0.0:* users:(("nginx",pid=29744,fd=8))
LISTEN 0 8192 0.0.0.0:8080 0.0.0.0:* users:(("docker-proxy",pid=2030,fd=8))

```

در این مثال:

* پورت `80` در اختیار Nginx است.
* پورت `443` در اختیار Nginx است.
* پورت `8080` در اختیار Docker است.

اکنون آزاد بودن پورت `18080` را بررسی کنید:

```bash
sudo ss -lntp | grep ':18080'

```

اگر خروجی نمایش داده نشد، پورت آزاد است. **هرگز سرویس‌های در حال اجرا را صرفاً برای آزاد کردن پورت متوقف نکنید** و به‌جای آن پورت آزاد دیگری انتخاب کنید.

## ⚙️ مرحله ۲: پیکربندی Nginx

باید Nginx را طوری تنظیم کنید که درخواست‌های چالش ACME را به پورت اختصاصی ACME هدایت کند. فایل پیکربندی Nginx که درخواست‌های ارسالی مستقیم به IP سرور را مدیریت می‌کند پیدا کنید.

**مسیرهای رایج فایل‌های پیکربندی:**

* `/etc/nginx/sites-enabled/`
* `/etc/nginx/conf.d/`

برای مشاهده پیکربندی فعال Nginx:

```bash
sudo nginx -T

```

در داخل بلوک `server` مربوط به HTTP که روی پورت `80` گوش می‌دهد، قطعه کد زیر را اضافه کنید:

```nginx
location ^~ /.well-known/acme-challenge/ {
    proxy_pass [http://127.0.0.1:18080](http://127.0.0.1:18080);

    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}

```

### نمونه پیکربندی کامل

```nginx
server {
    listen 80 default_server;
    listen [::]:80 default_server;

    server_name _;

    location ^~ /.well-known/acme-challenge/ {
        proxy_pass [http://127.0.0.1:18080](http://127.0.0.1:18080);

        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    location / {
        # Keep your existing application routing here.
    }
}

```

**نکات مهم:**

* اگر از قبل یک بلوک `default_server` دارید، همان را ویرایش کنید و از ساخت یک `default_server` تکراری خودداری نمایید.
* مسیر ACME باید **بدون** ریدایرکت شدن از HTTP به HTTPS در دسترس باشد.
* مطمئن شوید بلوک `server` درخواست‌هایی را که مستقیماً به IP عمومی شما ارسال می‌شوند، دریافت می‌کند.
* تنظیمات مسیریابی (Routing) اپلیکیشن‌های قبلی خود را دست‌نخورده نگه دارید.

### بررسی صحت تنظیمات و بارگذاری مجدد Nginx

```bash
sudo nginx -t

```

در صورت نبود خطا، Nginx را Reload کنید:

```bash
sudo systemctl reload nginx

```

با این کار Nginx بدون قطع کردن سرویس‌های فعلی به کار خود ادامه می‌دهد.

## 🔄 مرحله ۴: بررسی نصب گواهی

پس از صدور موفق گواهی، محل ذخیره فایل‌های آن را بررسی کنید. مسیر پیش‌فرض `acme.sh` معمولاً `/root/.acme.sh/` است.

یافتن فایل‌های مرتبط با گواهی:

```bash
sudo find /root/.acme.sh -type f \( -name '*.conf' -o -name '*.cer' -o -name '*.key' \)

```

جستجوی فایل پیکربندی مربوط به IP سرور (عبارت `YOUR_SERVER_IP` را با IP واقعی سرور جایگزین کنید):

```bash
sudo find /root/.acme.sh -type f -name '*.conf' | grep 'YOUR_SERVER_IP'

```

بررسی محتوای فایل پیکربندی گواهی:

```bash
sudo grep -E 'Le_HTTPPort|Le_ReloadCmd|Le_Webroot' /path/to/certificate.conf

```

باید خط زیر را مشاهده کنید:

```text
Le_HTTPPort='18080'

```

> ساختار دقیق پوشه‌ها ممکن است بسته به نوع نصب `acme.sh` و نوع گواهی متفاوت باشد (برخی نسخه‌ها از زیرپوشه `_ecc` استفاده می‌کنند).

## 🔁 مرحله ۵: اطمینان از تمدید خودکار (Auto-Renewal)

صدور موفق گواهی در بار اول، لزوماً به معنای عملکرد صحیح تمدید خودکار در آینده نیست. سه مورد زیر را حتماً بررسی کنید:

### ۵.۱. بررسی ذخیره شدن پورت ACME

در فایل پیکربندی گواهی باید مقدار زیر ثبت شده باشد:

```text
Le_HTTPPort='18080'

```

### ۵.۲. بررسی Cron Job مربوط به تمدید

وظایف زمان‌بندی‌شده کاربر `root` را بررسی کنید:

```bash
sudo crontab -l

```

باید دستور زمان‌بندی‌شده تمدید `acme.sh` را در خروجی ببینید. اگر `acme.sh` تحت کاربر دیگری نصب شده است، crontab آن کاربر را نیز بررسی کنید. برای یافتن مسیر فایل اجرایی:

```bash
sudo find / -name acme.sh -type f 2>/dev/null

```

### ۵.۳. بررسی پایداری تنظیمات Nginx

مطمئن شوید که مسیر چالش ACME در پیکربندی فعال Nginx وجود دارد:

```bash
sudo nginx -T | grep -A 10 'acme-challenge'

```

همچنین اطمینان حاصل کنید که Nginx پس از ریبوت سرور به‌صورت خودکار اجرا می‌شود:

```bash
sudo systemctl is-enabled nginx

```

### ⚠️ نکات مهم هنگام تمدید

در زمان تمدید خودکار مراحل زیر رخ می‌دهد:
۱. جاب زمان‌بندی‌شده `acme.sh` اجرا می‌شود.
۲. ابزار `acme.sh` از پورت ذخیره‌شده (`18080`) استفاده می‌کند.
۳. وب‌سرور Nginx درخواست چالش HTTP-01 را به این پورت هدایت می‌کند.
۴. سرویس Let's Encrypt چالش را تایید می‌کند.
۵. ابزار `acme.sh` گواهی را تمدید می‌کند.
۶. دستور استقرار یا بارگذاری مجدد (Reload) تنظیم‌شده، گواهی جدید را به سرویس مصرف‌کننده اعمال می‌کند.

> اطمینان حاصل کنید که دستور Reload/Deploy گواهی برای پنل یا سرویس استفاده‌کننده به‌درستی تنظیم شده است.

---

## 🛡️ مرحله ۶: پیکربندی فایروال (Firewall)

پورت عمومی HTTP باید برای دسترسی سرورهای Let's Encrypt باز بماند.

| پورت (Port) | پروتکل (Protocol) | سطح دسترسی (Access) |
| --- | --- | --- |
| `80` | TCP | عمومی (Public) |
| `443` | TCP | عمومی (در صورت استفاده از سرویس‌های HTTPS) |
| `18080` | TCP | فقط دسترسی محلی پراکسی (Local Proxy Only) |

**پورت `18080` را به‌صورت عمومی باز نکنید.** Nginx به `127.0.0.1:18080` متصل می‌شود.

با این حال، توجه داشته باشید که `acme.sh` در حالت Standalone ممکن است به‌جای `localhost` روی `0.0.0.0` گوش دهد. وضعیت شنود پورت را بررسی کنید:

```bash
sudo ss -lntp | grep ':18080'

```

اگر روی تمام اینترفیس‌ها (`0.0.0.0`) فعال است، دسترسی خارجی به پورت `18080` را در فایروال مسدود کرده و فقط اتصالات محلی (Local) را مجاز کنید. نیازی به باز کردن این پورت در UFW، iptables یا فایروال ابری نیست.

## 🧰 عیب‌یابی (Troubleshooting)

### ❌ خطای اشغال بودن پورت 80

* **پیام خطا:**
```text
tcp port 80 is already used by nginx
Please stop it first

```


* **علت:** Nginx از قبل روی پورت `80` فعال است و `acme.sh` نمی‌تواند شنودگر Standalone را روی آن راه‌اندازی کند.
* **راه‌حل:** Nginx را روشن نگه دارید، آن را برای فوروارد کردن درخواست‌های ACME تنظیم کنید، یک پورت محلی دیگر (مانند `18080`) انتخاب کنید و آن را در منوی مدیریت SSL پنل 3X-UI وارد نمایید.

### ❌ خطای اشغال بودن پورت انتخابی ACME

* **پیام خطا:**
```text
tcp port 8080 is already used by docker-proxy
Please stop it first

```


* **علت:** سرویس دیگری (مانند Docker) در حال استفاده از پورت انتخاب‌شده است.
* **راه‌حل:** یک پورت آزاد دیگر پیدا کنید (`sudo ss -lntp | grep ':18080'`)، از آن استفاده کرده و تنظیمات `proxy_pass` در Nginx را متناسب با آن به‌روزرسانی کنید.

### ❌ عدم توانایی Let's Encrypt در اعتبارسنجی IP

* **علل احتمالی:**
* پورت عمومی TCP `80` مسدود است.
* Nginx مسیر چالش ACME را فوروارد نمی‌کند.
* بلوک `server` اشتباهی در Nginx درخواست را دریافت می‌کند.
* پورت مقصد (Upstream) در تنظیمات Nginx اشتباه وارد شده است.
* آدرس IP وارد شده با IP عمومی ورودی سرور مطابقت ندارد.
* فایروال یا پراکسی سطح شبکه در درخواست تداخل ایجاد می‌کند.


* **دستورات بررسی:**
```bash
sudo nginx -t
sudo systemctl status nginx
sudo ss -lntp | grep -E ':(80|18080)\b'
sudo tail -n 100 /var/log/nginx/error.log

```



### ❌ شکست در تمدید خودکار

موارد زیر را بررسی کنید:
۱. مقدار ذخیره‌شده `Le_HTTPPort`.
۲. فعال بودن Cron Job مربوط به تمدید `acme.sh`.
۳. در دسترس بودن سرویس Nginx.
۴. وجود تنظیمات مسیر چالش ACME در Nginx.
۵. باز بودن پورت عمومی TCP `80`.
۶. صحیح بودن دستور استقرار یا Reload گواهی.

> به یاد داشته باشید: صدور موفق اولیه تضمینی برای پیکربندی صحیح تمدید خودکار نیست.

* [ ] دسترسی خارجی به پورت `18080` مسدود شده است.
* [ ] مکانیزم اعمال/Reload گواهی پس از تمدید پیکربندی شده است.
* [ ] سایر اپلیکیشن‌ها بدون مشکل روی پورت‌های `80` و `443` کار می‌کنند.

## 🎯 جمع‌بندی

با این معماری، Nginx همچنان مسئول مدیریت ترافیک عمومی HTTP باقی می‌ماند، در حالی که 3X-UI و `acme.sh` فرآیند صدور و تمدید گواهی را از طریق یک پورت شنودگر اختصاصی انجام می‌دهند.

**ایده اصلی:** Nginx را روشن نگه دارید و به‌جای متوقف کردن سرویس‌های فعلی، درخواست‌های چالش `ACME HTTP-01` را به یک شنودگر مجزای `acme.sh` هدایت کنید. این روش به شما اجازه می‌دهد چندین اپلیکیشن، ریورس پراکسی و کانتینرهای Docker را بدون وقفه اجرا کنید و هم‌زمان از گواهی SSL خودکار روی IP از Let's Encrypt بهره‌مند شوید.

> **نکته اجرایی:** این روش بر این فرض استوار است که نسخه نصب‌شده 3X-UI پورت سفارشی HTTP را ذخیره کرده و در زمان تمدید مجدداً از آن استفاده می‌کند. پس از اولین صدور موفق، حتماً تنظیمات `Le_HTTPPort`، جاب Cron تمدید و دستور استقرار گواهی را بررسی نمایید.
